# Aegis Vanguard

A local-first brand governance workspace with a React/TypeScript client and a FastAPI/SQLAlchemy API. SQLite schema initialization is additive: existing draft, finding, rule, decision, and audit records are not erased. Additional tables persist analysis runs, evidence references, draft versions, proposed edits, and rule snapshots.

The product runs without AI credentials. In that mode it labels analysis **rules-only** and only runs deterministic configured checks. When configured, OpenAI's Python SDK uses the Responses API with Pydantic structured output. Analysis remains read-only; a rewrite only changes a draft after a reviewer explicitly accepts it.

## Requirements

- Node.js and npm
- The existing Python environment at `backend\.venv`
- Backend dependencies from `backend\requirements.txt`

Install or restore backend dependencies from the project root:

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

## Start locally (Windows PowerShell)

### 1. Configure the optional AI provider

For rules-only operation, skip this step. To configure OpenAI, copy the placeholder file and edit `.env` locally:

```powershell
Copy-Item .env.example .env
notepad .env
```

Set `OPENAI_API_KEY` and optionally `OPENAI_MODEL`. `.env` is excluded from Git. The API never returns or logs the API key. Merely configuring a key does not mean a live request has succeeded; the UI/API report success only after a valid model response.

### 2. Start the API

In one PowerShell window:

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --reload
```

### 3. Start Vite

In a second PowerShell window:

```powershell
npm.cmd run dev
```

Open the Vite URL printed in the terminal (normally `http://localhost:5173`). API health is at `http://127.0.0.1:8000/api/health`, provider status is at `/api/intelligence/status`, and interactive API documentation is at `http://127.0.0.1:8000/docs`.

SQLite is created as `backend\aegis.db` on first API startup. To select another database:

```powershell
$env:AEGIS_DATABASE_URL = "sqlite:///C:/data/aegis-dev.db"
.\backend\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --reload
```

The frontend defaults to `http://127.0.0.1:8000/api`. Set `VITE_API_URL` before starting Vite to use another API base URL.

## Analysis, evidence, and review

1. Submit and save a draft.
2. Add source URLs and/or excerpts as user-supplied evidence references.
3. Run analysis. Configured deterministic checks always run. If OpenAI is configured and returns valid output, structured claim analysis is combined with those checks; otherwise, the result explicitly remains rules-only.
4. Inspect exact quoted claims, severity, policy links, evidence state, recommendations, and missing information.
5. Review proposed wording individually. Accepting a proposal creates a version; it never silently overwrites draft text.
6. A reviewer can approve, reject, or request changes. Requested-change drafts can be edited, saved as a new version, analyzed again, and resubmitted.
7. Inspect versioned policy rules and the audit trail.

Evidence URLs and excerpts are stored as **user-supplied and unverified**. This MVP does not retrieve URLs or verify source contents; there is therefore no server-side URL fetcher or external-source verification. No citations, evidence, or statistics are generated by the application. Model output is validated for schema, exact quote presence, known policy IDs, and supplied evidence IDs. A model result cannot publish or approve content.

The app is in **local single-user mode**. Authentication, user identity, and role-based permissions are not implemented. Reviewer attribution is a local label, not an authenticated identity. This deployment is intended for local evaluation, not a multi-user production environment.

## Railway hackathon deployment

The repository can be deployed as two Railway services from the same GitHub repository:

1. Create a backend service with root directory `/backend`, install command `pip install -r requirements.txt`, and start command `uvicorn main:app --host 0.0.0.0 --port $PORT`.
2. Generate a public domain for the backend. Add `OPENAI_API_KEY` only in the backend service's Railway Variables. Until a valid key is added and a real request succeeds, the app remains in rules-only mode.
3. Create a frontend service from the repository root. Use build command `npm ci && npm run build` and start command `npm run preview -- --host 0.0.0.0 --port $PORT`. Set the build variable `VITE_API_URL` to `https://<backend-domain>/api`.
4. Generate a public domain for the frontend. Set backend variable `AEGIS_CORS_ORIGINS` to exactly `https://<frontend-domain>` and redeploy both services.

Railway's default filesystem is ephemeral unless a volume is attached. Without a volume and an `AEGIS_DATABASE_URL` pointing to that volume, database writes can be lost on redeploy/restart. This deployment does not copy the local `backend\aegis.db` to a public host. Keep `.env` and API keys out of GitHub; `.env` is ignored.

## API highlights

- `GET /api/dashboard`, `GET /api/intelligence/status`
- `POST /api/submissions`; `GET /api/drafts`, `GET /api/drafts/{id}`
- `POST /api/drafts/{id}/analyze`, `GET /api/drafts/{id}/analyses`
- `POST /api/drafts/{id}/evidence`, `POST /api/drafts/{id}/assistant`
- `PUT /api/drafts/{id}/content`; `GET /api/drafts/{id}/versions`
- `POST /api/drafts/{id}/proposed-edits/{edit_id}/decision`
- `POST /api/drafts/{id}/review`
- `GET`, `POST`, and `PUT /api/brand-rules`; `GET /api/brand-rules/{id}/versions`
- `GET /api/findings`, `GET /api/audit`

Review decisions are rejected if draft content or brand policy versions changed after the latest analysis. Re-analyze before making the decision.

## Build and tests

```powershell
npm.cmd run build
npm.cmd run lint
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend -p "test_*.py" -v
```

Backend tests use a mocked analysis provider and do not require paid API calls. To validate a live OpenAI request, configure a valid key/model and run a draft analysis from the app; until that succeeds, report the integration as configured-but-not-verified or unavailable.
