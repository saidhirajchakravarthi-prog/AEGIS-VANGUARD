# Aegis Vanguard

A local-first brand governance workspace with a React/TypeScript client and a FastAPI/SQLAlchemy API. SQLAlchemy models define the schema; Alembic migrations version schema changes. SQLite is for local development and tests. Managed PostgreSQL is required for reliable production persistence.

The product runs without AI credentials. In that mode it labels analysis **rules-only** and only runs deterministic configured checks. When configured, OpenAI's Python SDK uses the Responses API with Pydantic structured output. Analysis remains read-only; a rewrite only changes a draft after a reviewer explicitly accepts it.

## Requirements

- Node.js and npm
- The existing Python environment at `backend\.venv`
- Backend dependencies from `backend\requirements.txt`
- Database migrations applied before starting the API

Install or restore backend dependencies from the project root:

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

## Start locally (Windows PowerShell)

Install backend dependencies and apply the initial schema once from the repository root:

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\backend\.venv\Scripts\python.exe -m alembic -c alembic.ini upgrade head
```

The first migration adopts an existing pre-Alembic SQLite workspace without deleting records. Future schema changes must be added as new immutable Alembic revisions. Normal API startup does not implicitly create the schema. For the Vercel SQLite demo only, a cold instance runs the versioned migration so the demo can operate; its records remain ephemeral. For PostgreSQL, apply migrations as a release step before deployment.

### 1. Configure the optional AI provider

For rules-only operation, skip this step. To configure OpenAI, copy the placeholder file and edit `.env` locally:

```powershell
Copy-Item .env.example .env
notepad .env
```

Set `OPENAI_API_KEY` and optionally `OPENAI_MODEL`. `.env` is excluded from Git. The API never returns or logs the API key. Merely configuring a key does not mean a live request has succeeded; the UI/API report success only after a valid model response.

### 2. Start the API

In one PowerShell window:

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --reload
```

### 3. Start Vite

In a second PowerShell window:

```powershell
npm.cmd run dev
```

Open the Vite URL printed in the terminal (normally `http://localhost:5173`). API health is at `http://127.0.0.1:8000/api/health`, provider status is at `/api/intelligence/status`, and interactive API documentation is at `http://127.0.0.1:8000/docs`.

The local SQLite file is `backend\aegis.db`. To select another database:

```powershell
$env:AEGIS_DATABASE_URL = "sqlite:///C:/data/aegis-dev.db"
.\backend\.venv\Scripts\python.exe -m alembic -c alembic.ini upgrade head
.\backend\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --reload
```

For managed PostgreSQL, set `AEGIS_DATABASE_URL` to a SQLAlchemy URL such as `postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require`. Keep the real URL in a local ignored `.env` or the hosting provider's secret environment-variable settings; do not put credentials in Git. Run the Alembic upgrade against the same database before deploying the API. `postgres://` and `postgresql://` URLs are normalized to the psycopg driver.

The frontend defaults to `http://127.0.0.1:8000/api`. Set `VITE_API_URL` before starting Vite to use another API base URL.

## Analysis, evidence, and review

1. Submit and save a draft.
2. Add source URLs and/or excerpts as user-supplied evidence references.
3. Run analysis. Configured deterministic checks always run. If OpenAI is configured and returns valid output, structured claim analysis is combined with those checks; otherwise, the result explicitly remains rules-only.
4. Inspect exact quoted claims, severity, policy links, evidence state, recommendations, and missing information.
5. Review proposed wording individually. Accepting a proposal creates a version; it never silently overwrites draft text.
6. A reviewer can approve, reject, or request changes. Requested-change drafts can be edited, saved as a new version, analyzed again, and resubmitted.
7. Inspect versioned policy rules and the audit trail.

Evidence URLs and excerpts are stored as **user-supplied and unverified**. This MVP does not retrieve URLs or verify source contents; there is therefore no server-side URL fetcher or external-source verification. No citations, evidence, or statistics are generated by the application. Model output is validated for schema, exact quote presence, known policy IDs, and supplied evidence IDs. A model result cannot publish or approve content.

The app is in **local single-user mode**. Authentication, user identity, and role-based permissions are not implemented. Reviewer attribution is a local label, not an authenticated identity. Do not use this deployment for confidential or multi-user governance records.

The Audit history page includes a controlled Governance Learning summary. It reports repeated findings across the latest completed approve/reject decisions in a selected time window, with linked draft, finding, and decision IDs. It is descriptive, flags actor labels as unverified, and only recommends human policy review: it never changes active rules and does not claim that repeated patterns caused a decision.

## Vercel hackathon deployment

The `vercel.json`, root `requirements.txt`, and `api/index.py` configure the Vite build and FastAPI function in one project. Import the GitHub repository in Vercel with the repository root as the project root. The production frontend calls the same-origin `/api` path; local development continues to use `http://127.0.0.1:8000/api`.

Set `AEGIS_DATABASE_URL` to managed PostgreSQL in Vercel Project Settings before deploying for durable operation. Use the provider connection URL, enable its required TLS settings, and keep it in Vercel's secret environment-variable settings. Run `alembic upgrade head` against this database as a release step before routing traffic to the new version. Do not configure SQLite under `/tmp` for governance records. Vercel without `AEGIS_DATABASE_URL` fails closed at startup. A configured SQLite URL is allowed only as a temporary demo: each cold instance applies the versioned migration, and the API reports that its storage is not persistent; records can disappear between serverless instances or deployments.

- `OPENAI_API_KEY` — optional; enter only in Vercel's secret environment-variable UI. `OPENAI_MODEL` is optional and defaults to `gpt-4.1-mini`.

Vercel serverless storage under `/tmp` is ephemeral and not a durable database. `/api/health` and `/api/intelligence/status` report the database kind, whether a non-SQLite database is configured, and whether Alembic has been applied. This status does not independently verify that a database provider offers backups or durability. The local `backend\aegis.db` is not copied to the public host. Keep `.env` and API keys out of GitHub; `.env` is ignored.

After deployment, verify `/api/health` and `/api/intelligence/status`. The application must continue to report rules-only until a valid key is configured and an actual model request succeeds. Do not report live AI based solely on key configuration. The production API remains unauthenticated until a supported identity provider is provisioned and enforced; the frontend is not an access-control boundary.

## API highlights

- `GET /api/dashboard`, `GET /api/intelligence/status`
- `POST /api/submissions`; `GET /api/drafts`, `GET /api/drafts/{id}`
- `POST /api/drafts/{id}/analyze`, `GET /api/drafts/{id}/analyses`
- `POST /api/drafts/{id}/evidence`, `POST /api/drafts/{id}/assistant`
- `PUT /api/drafts/{id}/content`; `GET /api/drafts/{id}/versions`
- `POST /api/drafts/{id}/proposed-edits/{edit_id}/decision`
- `POST /api/drafts/{id}/review`
- `GET`, `POST`, and `PUT /api/brand-rules`; `GET /api/brand-rules/{id}/versions`
- `GET /api/findings`, `GET /api/audit`
- `GET`, `POST /api/governance/learning`; `GET /api/governance/learning/runs`

Review decisions are rejected if draft content or brand policy versions changed after the latest analysis. Re-analyze before making the decision.

## Build and tests

```powershell
npm.cmd run build
npm.cmd run lint
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend -p "test_*.py" -v
```

Backend tests use a mocked analysis provider and do not require paid API calls. To validate a live OpenAI request, configure a valid key/model and run a draft analysis from the app; until that succeeds, report the integration as configured-but-not-verified or unavailable.
